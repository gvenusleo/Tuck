# Tuck 设计文档

Tuck 通过菜单栏图标和全局快捷键提供终端入口。每个标签页持有独立的本地 shell 会话，面板的展开、收起和标签切换不影响后台命令执行。

## 目标与范围

首版面向 macOS，采用菜单栏应用形态，不显示 Dock 图标。用户可通过固定的 Option + 空格快捷键展开或收起终端。

当前支持多标签页、终端外观设置和开机启动，不包含分屏、标签分组、拖拽排序、通知和自动更新。会话不跨应用退出或电脑重启恢复，需要跨应用生命周期保持进程时可自行使用 tmux 或 SSH。扩展上述功能前，应先明确其交互与生命周期要求，再调整实现。

Windows 和 Linux 沿用 MyGo 的跨平台接口，不增加平台专用实现，其运行行为不属于首版验收范围。Windows 使用终端插件默认的 PowerShell。

## 用户交互

| 操作 | 预期行为 |
| --- | --- |
| 启动 Tuck | 显示菜单栏图标，不自动展开面板或启动 shell |
| 首次展开终端 | 创建会话并展开面板，键盘焦点进入终端 |
| 按 Option + 空格或点击菜单栏图标 | 切换面板的展开与收起状态 |
| 点击面板外部或切换应用 | 收起面板，保持会话运行 |
| 再次展开终端 | 显示上次选中的标签，保留所有会话的工作目录、变量和输出；没有会话时创建新会话 |
| 右键点击菜单栏图标 | 收起面板，显示“打开 Tuck”、“设置”和“退出 Tuck”菜单 |
| 选择“设置” | 打开或唤回唯一的设置窗口，关闭设置不结束终端会话 |
| 再次启动应用 | 唤回已有实例并展开终端，不创建第二个会话 |
| 按 Escape 或 Control + C | 交由终端程序处理，保留 Vim 退出编辑模式、命令中断等常规行为 |
| 普通命令执行结束 | 返回当前 shell 的提示符 |
| 按 Command + T 或选择标签栏右键菜单中的“新建标签页” | 在末尾创建独立会话并选中，焦点进入终端 |
| 输入 `exit`、shell 自身退出或按 Command + W | 结束对应会话；活动标签关闭后优先选右侧，其次左侧；后台标签关闭不切换当前会话；最后一个标签关闭后收起面板 |
| 选择“退出 Tuck” | 关闭面板、释放全部终端并移除菜单栏图标 |

每次创建会话时均使用用户默认的登录 shell，初始目录为用户主目录，不复制其他会话的环境变量或执行状态。明确关闭标签或退出应用时结束对应会话，不增加确认弹窗。已脱离终端的进程由 shell 和操作系统管理，Tuck 不保证清理所有后代进程。

## 界面

面板内容默认尺寸为 720 × 420 DIP，包含标签栏，终端填满剩余区域且不留上下内边距，文字紧贴标签栏；横向保留插件默认的 6 DIP，与标签文字左对齐。不设标题栏或状态栏。宽高可在设置中修改，接受正整数，不设固定产品上限。每次展开时通过托盘中心点确定所在屏幕，读取可用区域，四周各预留 16 DIP 给系统箭头和边框，再限制实际内容尺寸；托盘位置不可用时使用主屏幕。适配屏幕不改写保存的期望尺寸。macOS 使用系统 NSPopover，保留系统的箭头、阴影、圆角和菜单栏图标高亮。

终端默认采用深色主题 `Ghostty Default Style Dark`，背景色为 `#282c34`，默认文字颜色为 `#ffffff`。主题可在设置中选择，不随系统外观切换。默认字体为 `JetBrainsMono Nerd Font`，字号为 12 DIP，可选择系统中的等宽字体并设置 8 到 48 DIP 的字号；字体缺失时回退到其他字体。应用不附带字体文件，复制粘贴、滚动、链接和上下文菜单由终端插件提供。若后续引入系统材质，应同时调整终端背景透明度和文字对比度。

只有一个标签时隐藏标签栏，终端占满面板；两个及以上标签时显示标签栏，默认在上方，可在设置中移到下方。使用 MyGo `ui.TabsBase` 保留原生交互及无障碍语义，背景、文字和选中态从终端主题取色，避免与终端产生色块分割。栏高 22 DIP，标签字体固定为 11 DIP，标题居中，无圆角、外侧留白或标签间距；每项左右内边距 6 DIP。标签宽度在 80～180 DIP 之间，长标题按可用宽度省略，不显示关闭图标或右侧操作按钮。新建使用 Command + T，关闭当前标签使用 Command + W；标签栏右键菜单也可新建、关闭指向的标签、前后切换或从全部标签中选择。标签区保留横向滚动但隐藏滚动条，选中时使用框架的 `ScrollIntoView` 露出对应项。单标签与多标签切换只调整布局，不重建会话。

标签标题优先读取 `Terminal.Dir()`（shell 上报的 OSC 7），显示目录末段；目录为用户家目录时显示 `~`，悬停始终显示完整路径。没有目录信息时使用终端上报的标题，再按当前标签位置命名为“终端 N”；关闭标签后默认名称连续编号，内部会话 ID 保持稳定。每次重绘读取最新目录，不解析提示符或轮询系统进程。

所有会话沿用 MyGo 的默认 shell 启动方式。Tuck 仅使用 shell 已有的目录和标题上报信息，不注入 shell 专用脚本、不覆盖 `ZDOTDIR`，也不修改用户启动配置。目录信息缺失时使用上述标题回退规则。

设置窗口内容固定为 520 × 400 DIP，使用标准窗口标题栏，不可缩放、最大化或进入全屏。顶部居中放置 MyGo 原生 Segmented control，包含“外观”和“通用”。表单整体水平居中，标签保持右对齐。外观页使用可搜索的主题、字体选择框，标签栏位置使用“上方 / 下方”分段控件，另有字号、面板宽度和高度输入框，宽高标签标明 DIP 单位；通用页提供开机启动开关。设置控件沿用 MyGo 默认样式，设置窗口跟随系统明暗，终端配色独立于设置窗口。

应用图标采用白色底板与 `#2177b8` 的小写 `t`，图形按包围盒严格居中，只保留一层轻微投影。菜单栏图标保留相同字形，放大后以单色模板输出，随系统菜单栏外观变化。

## 技术方案

应用使用 Go 和 MyGo 原生 UI，终端由 `plugins/terminal` 提供。插件负责伪终端（PTY）、shell 进程、输入编码、滚动历史和绘制，运行时加载 `libghostty-vt` 完成终端模拟。构建保持 `CGO_ENABLED=0`，不引入 WebView 或自建命令执行协议。

程序入口位于 `cmd/tuck`，仅负责调用 `internal/app.Run()` 并报告启动错误。`internal/app` 管理应用生命周期、托盘、快捷键、终端浮窗和设置窗口；`internal/config` 负责 JSON 配置的路径、默认值、校验和读写。

```text
Tuck 应用
├── Tray：应用运行期间存在，提供展开、收起和退出入口
├── Sessions：每项持有稳定 ID、Terminal 和标题，独立管理 PTY 与 shell
├── ActiveID：当前显示的会话
└── Flyout：展开时创建，收起时关闭
    ├── Tabs：多会话时显示，提供标签及右键会话菜单
    └── terminal.View：只显示活动会话的 Terminal
```

### 终端归应用持有，浮窗按需创建

终端与浮窗采用不同的生命周期。没有会话时，展开面板会调用 `terminal.New` 创建第一个终端。每次新建标签再创建一个终端。后续展开只创建新的浮窗，通过 `terminal.View` 显示活动会话；切换标签不重新创建终端。shell 退出后只移除对应标签并释放终端，最后一个标签结束时才收起浮窗，不自动重启 shell。同一时刻最多存在一个浮窗。

会话使用稳定 ID，列表下标仅用于显示顺序、默认名称和数字快捷键。关闭时先从列表移除，再释放终端；标题、退出回调回到主线程后检查 ID，忽略已关闭会话的迟到事件。新建和切换后请求终端焦点；标签栏通过键盘获得焦点时保留原生导航。视图身份绑定会话 ID，不复用其他会话的输入状态。

浮窗关闭时，`OnClosed` 仅清理窗口引用，不关闭终端。回调会核对窗口身份，避免旧窗口的关闭通知覆盖新窗口引用。`App.OnWindowAllClosed` 阻止最后一个浮窗关闭时自动退出应用。

隐藏期间，插件继续读取 PTY 输出并更新终端状态。重新展开时应立即显示最新内容，不依赖后续命令输出触发刷新。插件的 `viewOf` 会更新绘制服务引用，应用不保存旧窗口的绘制服务，也不维护额外的输出副本。滚动历史采用插件默认的约 10 MB 上限，shell 环境由插件处理。

视图函数只构建界面，不创建会话或执行外部操作，以免多次重建视图产生重复进程。

### 使用系统浮窗承载终端

`mygo.NewFlyout` 通过 `Tray` 锚定菜单栏图标，采用 `PlacementBottom`，启用 `Focusable`、`Shadow` 和 `Popover`。框架负责定位和点击外部关闭，应用不自行计算托盘坐标，也不启用仅适用于 Web 内容的 `FitContent`。

这一方案沿用 MyGo 的 `examples/menubar-flyout`。相比普通无边框窗口，可减少手动定位和失焦处理。若后续需要拖动、缩放或固定窗口，再评估普通窗口方案。多显示器、缩放和屏幕边缘下的定位仍需人工验收。

macOS 的 NSPopover 会接管定位控件上的按下事件。再次点击菜单栏图标时，框架的 `popoverShouldClose` 需要允许关闭，不能依赖随后触发托盘点击回调完成切换。当前固定的 MyGo 版本已包含这一修复，无 popover 的浮窗继续使用托盘点击切换。

### 全局快捷键、窗口内快捷键与单实例

终端浮窗通过 `Context.OnShortcut` 注册 Command + T/W 新建和关闭标签，Command + Shift + [ / ] 循环切换，Command + 1～8 按位置选择，Command + 9 选择最后一个标签，Command + 逗号打开设置。不存在的数字位置无操作。快捷键只在终端浮窗内生效，不占用终端的 Escape、Control + C/D、Tab 和普通方向键。设置窗口中的 Command + W 只关闭设置。macOS 原生菜单会先处理 Command + W，因此应用菜单中的关闭动作同样按目标窗口分派。当前 MyGo 的 NSPopover 没有登记到 `FocusedWindow()`，菜单回调可能收到 nil；此时使用当前浮窗关闭活动标签。菜单提供明确的设置窗口时只关闭设置，不影响会话。

托盘创建成功后，应用通过 `mygo.GlobalShortcut.Register("Alt+Space", a.toggle)` 注册全局快捷键。回调在主线程执行，与托盘点击共用展开和收起逻辑。注册失败时记录错误，保留托盘入口，退出清理时注销快捷键。

启动时调用 `App.RequestSingleInstanceLock`。第二个进程通过 `App.OnSecondInstance` 通知已有实例展开终端，然后退出。macOS 的重新打开事件由 `App.OnActivate` 处理。两种请求都经 `App.WhenReady` 调度，避免托盘尚未创建时丢失展开请求。

macOS 右键菜单仅在弹出期间设置到托盘，关闭后解除，避免常驻菜单接管左键点击。Linux 的 AppIndicator 仅提供菜单入口，用户通过“打开 Tuck”展开终端，框架无法获取托盘位置时居中显示。

### 设置与持久化

配置默认位于 `~/.config/tuck/config.json`。设置了绝对路径的 `XDG_CONFIG_HOME` 时，使用 `$XDG_CONFIG_HOME/tuck/config.json`。配置结构如下：

```json
{
  "terminal_theme": "Ghostty Default Style Dark",
  "terminal_font": "JetBrainsMono Nerd Font",
  "terminal_font_size": 12,
  "terminal_width": 720,
  "terminal_height": 420,
  "terminal_tab_position": "top"
}
```

首次启动没有配置时使用默认值，首次修改外观时创建目录和文件。缺少字段时补默认值，标签栏位置接受 `top` 和 `bottom`，旧配置默认 `top`。JSON 损坏或字段无效时显示错误并使用默认配置；指定主题无法加载时仅回退主题，保留有效的字体与字号。启动时不覆盖原文件。

外观修改在后台保存，使用同目录临时文件写入、同步并替换原文件。字号、宽度和高度编辑期间只更新草稿，离开数值输入区域、设置窗口失焦或关闭以及应用退出前提交保存，避免逐字输入被保存期间的禁用状态打断。成功后通过 `Terminal.SetFont` 和 `Terminal.SetTheme` 应用到全部现有终端，不重建 shell 或丢失输出；新会话使用最新设置。标签栏位置保存成功后只刷新布局，失败时恢复原选项。宽高在下次展开时用于创建浮窗，沿用原终端会话。保存期间不禁用表单、不显示保存提示：这期间的改动会排队，当前保存结束后再写一次，避免快速保存造成的整页闪烁。失败时恢复原值并重置控件的编辑状态，避免显示未保存的文字。界面仅显示简短错误，完整原因记录到日志。退出时等待正在进行的配置写入。

开机启动使用 `App.SetOpenAtLogin`，状态通过 `App.OpenAtLogin` 从系统读取，不在 JSON 中保存第二份状态。打开设置和应用重新获得焦点时刷新，尊重用户在系统设置中的修改。macOS 需要运行 `.app` 包；注册失败或需要系统批准时，开关恢复到实际状态并显示提示。应用启动时不自动重新注册登录项。

### 线程、异常与退出

应用状态只在主线程读写。托盘回调、窗口生命周期和视图构建遵循 MyGo 的主线程模型，不向后台任务传递 `ui.Context`、临时 `ui.Element` 或旧窗口引用。

终端的 `OnTitle`、`OnExit` 在插件的 goroutine 中执行，通过独立的 goroutine 调度 `RunOnMain`，不在终端回调中等待主线程。shell 退出后由主线程按会话 ID 关闭对应标签；后台会话退出不展开面板。创建或延迟启动失败时显示错误对话框，保留其他会话和托盘。应用已开始退出时，忽略终端回调，由应用退出流程统一清理资源。

退出流程先设置退出标记，停止接受展开请求，由框架关闭窗口，并在退出清理中注销快捷键、释放终端和销毁托盘。应用不额外实现进程监督器。托盘创建或默认主题加载失败时显示系统错误对话框并退出，防止留下没有操作入口的后台进程。

## 开发与构建

项目使用 [mise](https://mise.jdx.dev/) 管理工具版本和任务，固定 Go `1.27.3`。MyGo CLI 以 Go tool 形式记录在 `go.mod` 中，通过 `go tool mygo` 调用，不依赖全局安装的 CLI。`mygo.json` 的 `main` 字段设为 `./cmd/tuck`，开发和构建命令仍在项目根目录运行。

MyGo 固定为 `v0.7.5-0.20261103074229-64d9abeb2951`，包含 macOS popover 修复。Go 会自动下载依赖，开发无需准备相邻的 MyGo 源码目录。

在项目根目录执行：

```sh
mise trust
mise install
mise run dev
```

开发命令准备终端动态库并启动热重载。首次准备依赖需要网络，本项目开发不需要 Bun 或 C 工具链。

| 命令 | 用途 |
| --- | --- |
| `mise run dev` | 启动开发应用并启用热重载 |
| `mise run fmt` | 格式化 Go 代码 |
| `mise run fmt-check` | 检查格式，不改写文件 |
| `mise run vet` | 执行 Go 与 MyGo 静态检查 |
| `mise run icon` | 重新生成应用图标与菜单栏图标 |
| `mise run ci` | 执行格式检查、静态检查和本机打包 |
| `mise run build` | 构建本机应用包及安装包 |
| `mise run install` | 构建后安装到 `/Applications/Tuck.app`，替换已有版本 |

其他 Go 命令通过 `mise exec -- go ...` 执行。

### 打包与分发

应用名称为 Tuck，模块路径为 `liuyu.xin/tuck`，应用标识为 `xin.liuyu.tuck`。应用版本及输出目录由 `mygo.json` 管理。

官方构建命令识别终端插件，将 `libghostty-vt` 随应用打包。应用不使用开发机上的绝对库路径，也不单独分发缺少动态库的 Go 可执行文件。安装后无需额外安装 Go、Bun、Ghostty 或 Zig。

Apple Silicon Mac 的输出位于 `build/darwin-arm64/`，包含 `Tuck.app` 和 DMG。构建后可直接打开应用：

```sh
mise run build
open build/darwin-arm64/Tuck.app
```

当前构建仅供本机试用，尚未进行 Developer ID 签名、公证或公开发布。Windows 和 Linux 的打包及运行验收另行安排。

## 验证与验收

`mise run ci` 负责格式、静态检查与打包，`mise exec -- go test ./...` 验证配置读写与设置控件交互。自动化测试不代替真实桌面中的交互验收。以下项目需在打包后的应用中人工确认，未完成的项目不记为已验证。

| 验收项目 | 检查内容 |
| --- | --- |
| 启动与单实例 | 仅显示一个菜单栏图标，无 Dock 图标或自动展开的面板，重复启动会展开已有实例 |
| 首次展开 | 可立即输入命令，面板尺寸和焦点正确 |
| 会话保持 | 执行 `cd /tmp`、设置变量并记录 shell PID，反复收起和展开后保持不变 |
| 隐藏期间输出 | 收起面板后完成持续输出的命令，重新展开可见最终结果，进程不因输出未读取而阻塞 |
| 重复展开与收起 | 持续输出期间反复点击图标、点击外部及切换应用，无重复 shell、空白画面或意外退出 |
| 终端交互 | Vim 的 Escape、Control + C、中文输入法、复制粘贴、滚动和上下文菜单正常，终端菜单不导致面板误关闭 |
| 全局快捷键 | 在其他应用中按 Option + 空格可展开并输入，再次按键收起，快捷键冲突时仍可通过托盘操作 |
| 显示适配 | 多显示器、不同缩放和屏幕边缘下定位合理，系统明暗外观下图标与文本清晰 |
| 退出与释放 | 在从未展开、展开、收起和命令运行时分别退出，确认图标移除、会话释放且快捷键注销 |
| 会话结束与重建 | 当前和后台标签退出时选择正确，最后一个标签结束后收起；再次展开创建新会话，使用默认目录且不保留原会话变量 |
| 多标签与快捷键 | 新建、鼠标/菜单/快捷键切换、循环与数字定位正确，输入进入活动会话；独立目录、变量和输出不串到其他标签；迟到回调不会误关其他会话 |
| 标签布局 | 单标签隐藏、多标签上下布局、居中标题、窄面板、深浅色终端主题正确；选中项可见、背景与终端统一且无滚动条或关闭图标；位置保存失败恢复原值 |
| 目录标题 | shell 已上报目录时显示目录末段，家目录显示 `~`；缺少目录时回退到终端标题，再回退到“终端 N”；用户原有 shell 启动配置保持不变 |
| 异常处理 | 动态库不可用或 shell 启动失败时错误可见，不留下无入口的后台应用 |
| 设置窗口 | 重复打开只有一个窗口，尺寸固定，标签与键盘操作正常，关闭设置后托盘和会话继续运行 |
| 外观设置 | 搜索并切换主题和字体、修改字号后原会话立即更新，重启应用后保留配置，保存失败时错误可见 |
| 面板尺寸 | 修改宽高后下次展开生效，shell PID、工作目录和输出保留；超过屏幕可用区域时缩小显示，切换到较大屏幕后恢复期望尺寸，重启后配置保留 |
| 开机启动 | 在 `.app` 包中切换登录项，系统中的状态一致，登录后只显示托盘，系统中禁用后应用不擅自重新启用 |
| 独立运行 | 应用不依赖开发机上的源码目录、Go 工具链或 Ghostty 安装即可运行 |
